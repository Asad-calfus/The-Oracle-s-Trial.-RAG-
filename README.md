# SmartDoc — Document Q&A using RAG

SmartDoc lets you upload a PDF and ask questions about it. It answers using
only the content of the uploaded documents, and always shows which
file/page the answer came from — it never invents an answer or a citation.

## Architecture

```
Upload flow:
  PDF -> extract text (per page) -> split into chunks -> embed each chunk
      -> store in ChromaDB (with source file, page, chunk_id metadata)

Question flow:
  Question -> embed -> find top-K most similar chunks in ChromaDB
      -> drop chunks that aren't similar enough (score filter)
      -> send remaining chunks + question to the LLM (strict prompt)
      -> return answer + citations (from chunk metadata, not the LLM)
```

Frontend (Streamlit) and backend (FastAPI) are two separate processes that
only talk over HTTP — the frontend never touches the database or the LLM
directly.

## Folder structure

```
backend/
  config.py       - all settings in one place (paths, models, thresholds)
  ingest.py       - PDF -> text -> chunks -> vector store
  vectorstore.py  - opens/writes to the Chroma vector database
  rag.py          - retrieval + hallucination checks + LLM call + citations
  main.py         - FastAPI app: /health, /upload, /query
frontend/
  app.py          - Streamlit UI, calls the backend over HTTP
data/
  documents/      - uploaded PDFs
  chroma/         - the persistent vector database (created on first use)
```

## Setup

1. Create and activate a virtual environment:
   ```
   python3 -m venv .venv
   source .venv/bin/activate
   ```
2. Install dependencies:
   ```
   pip install -r requirements.txt
   ```
3. Copy `.env.example` to `.env` and add your own OpenAI API key:
   ```
   OPENAI_API_KEY=sk-...
   ```

## Running

Start the backend (auto-restarts on code changes):
```
uvicorn backend.main:app --reload --port 8001
```

Start the frontend, in a separate terminal (with `.venv` activated again):
```
streamlit run frontend/app.py
```

Open the URL Streamlit prints, upload a PDF, then ask a question.

## How it works

- **Ingestion** (`ingest.py`): `PyPDFLoader` extracts text per page.
  `RecursiveCharacterTextSplitter` breaks each page into overlapping chunks
  (`CHUNK_SIZE` / `CHUNK_OVERLAP` in `config.py`). Each chunk is embedded
  with OpenAI's `text-embedding-3-small` and saved to ChromaDB along with
  its source filename, page number, and a chunk id.

- **Retrieval** (`rag.py`): the question is embedded the same way, and
  Chroma returns the `RETRIEVAL_TOP_K` most similar chunks, each with a
  distance score (lower = more similar).

- **Hallucination protection — two independent layers:**
  1. *Score filter*: chunks with a distance above
     `SIMILARITY_SCORE_THRESHOLD` are dropped before they ever reach the
     LLM.
  2. *Strict prompt*: the LLM is instructed to answer **only** from the
     given context, and to reply exactly `"I don't know based on the
     uploaded documents."` if the answer isn't there. This catches cases
     the raw distance score can't cleanly separate (see Known Limitations).

- **Citations**: filename and page number always come from the chunk
  metadata attached during ingestion — never generated by the LLM. This
  is what guarantees a citation can't be wrong or made up.

## Known limitations

These were found through real testing, not guessed in advance:

- **Broad/summary questions** ("what is this document about?") often fail,
  because no single chunk describes the whole document's topic — this is
  a limitation of chunk-based retrieval in general, not a bug.
- **The score threshold is a blunt instrument.** Testing showed relevant
  chunks scoring anywhere from ~1.0 to ~1.7 depending on how the question
  was phrased, and unrelated chunks scoring in a similar range — so a
  single fixed number can't perfectly separate "relevant" from
  "irrelevant." The strict prompt (layer 2 above) is the real safety net.
- **Scanned/image-based PDFs won't work.** `PyPDFLoader` only reads real
  embedded text, not text inside images — there's no OCR step.
- **Re-uploading the same PDF adds duplicate chunks.** There's no
  dedup/upsert check on ingestion, so uploading a file twice stores its
  chunks twice.

## Tech stack

FastAPI, Streamlit, LangChain, ChromaDB, OpenAI (`gpt-4o-mini` for
answers, `text-embedding-3-small` for embeddings).
